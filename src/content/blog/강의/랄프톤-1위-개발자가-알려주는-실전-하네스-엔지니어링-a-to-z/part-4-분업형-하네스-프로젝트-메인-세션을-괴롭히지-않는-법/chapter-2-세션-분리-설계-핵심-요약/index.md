> **한 문장.** 일을 여러 세션으로 **떼어내고**(이유 = 품질), 떼어낸 결과를 정해진 양식으로 **다시 묶는다**(도구 = 핸드오프). 이 둘이 한 쌍이다.

## 1. 왜 떼어내나

질문(ask) · 생성(build) · 검수(review)를 한 대화창에 다 몰면 편하지만, 세 가지가 망가진다.

- **추측(환각)** — 모호한 자리를 멈춰 묻지 않고 "아마 이런 뜻이겠지"로 메운다.
- **도미노** — 잘못 메운 값이 다음 단계 입력이 되어 번진다.
- **검수 무력화** — 자기가 만든 걸 자기가 검수하면 너그럽게 통과시킨다.

→ 셋을 관통하는 한 단어는 **편향**. 그래서 검수는 작업 과정을 모르는 독립 컨텍스트에 맡긴다. **세션 경계 = 편향 · 환각 방화벽.**

※ 정정 — 세션 분리의 배경이던 앤트로픽 요금 개편(SDK · 헤드리스 크레딧 차감)은 2026년 6월 15일 전면 중단됐다. 나누는 진짜 이유는 비용이 아니라 품질.

## 2. 떼는 방법 두 가지

| | 종속형 (서브에이전트) | 분리형 (독립세션) |
|---|---|---|
| 메인 세션 | 있음, 부모가 소유 | 없어도 됨 |
| 런타임 | 부모 것을 빌려 씀 | 직접 만들어야 돈다 |
| 컨텍스트 | 결과가 메인에 병합 (오염 경로) | 독립, 병합 없음 |
| 연결 | 부모-자식 spawn | 프로토콜 · API · MCP |
| 도구 | 부모 것 상속 | 세션마다 알려줘야 함 |
| 사례 | 클로드 코드 서브에이전트 | 우로보로스, 헤르메스, 오마이 오픈에이전트 |

→ **서브에이전트는 쉽지만 메인을 오염시킬 수 있고, 독립세션은 깨끗하지만 런타임을 직접 지어야 한다.** 세션 밖 자체 런타임이 결과 합치기 · 도구 관리 · 메모리 동기화까지 하면 그게 에이전트 OS.

## 3. 묶는 도구: 핸드오프

**"세션은 끝나도 양식은 남는다."** 세션의 대화 · 중간 메모는 사라지고, 메인에게 넘긴 결과 한 장만 남는다. 그러니 설계 대상은 기억이 아니라 **양식**이다.

- **왜 고정하나** — 형식이 들쭉날쭉하면 그 뜻 판단을 메인의 LLM 해석에 기대게 되고, LLM은 흔들리니 결정성(같은 입력 → 같은 처리)이 깨진다. 형식이 고정되면 코드가 같은 칸을 읽어 분기한다. **모델은 못 믿어도 형식은 믿게 만든다.**
- **에러 = 데이터** — `success: true / false` 칸을 맨 위에 둔다. 성공·실패 봉투 겉모양이 같아 메인은 값만 읽고 갈림길을 고른다. 실패에도 `path: B`처럼 다음 경로가 정해져 있다.
- **타임아웃 = 사실이 아니라 약속** — "시간 초과 = 실패"가 아니라 "얼마나 걸릴지 어림한 추정값". "진행 중", "오래 걸림" 신호도 형식에 넣어야 받는 쪽이 침묵을 실패로 오해 안 한다.
- **다음 행동을 비우면 사람이 떠안는다** — BMAD(옛 v4): 역할(PM · SM · QA · Dev)은 나눴는데 다음에 누굴 부를지 결과에 없어, 결국 만능 하나(갓 에이전트)로 수렴해 분리 이점이 사라짐. 병은 갓 에이전트가 아니라 "다음 행동"을 비운 양식.
- **계약서로 쓴다** — `## 다음 행동` 밑 "알아서 해줘"(X) → `next_action: RETRY`(O). 판정은 **enum 하나**(통과 / 재작업 / 재질문 / 종료). 값이 유한해야 셀 수 있고, 세야 성능을 측정·개선한다.
- **거짓말을 코드로 잡는다** — "받은 지시"와 "한 일"을 한 장에 나란히 두면, "제목 채웠다"는 주장과 실제 파일을 코드가 대조한다(LLM에게 안 물음).

## 4. 그 9칸은 외울 정답이 아니다

실습 양식 = From task 5칸(목적 · 입력 · 범위 · 금지 · 완료조건) + Result 4칸(결과 요약 · 판정 · 남은 질문 · 다음 세션의 첫 행동) = **9칸**.

**중요** — 이 9칸은 강사가 자기 업무에 맞춰 뽑은 예시지 법전이 아니다. 이름부터 `v1`(고쳐 나갈 자리). 본인 업무가 다르면 칸 이름 · 개수도 달라진다. 외울 건 칸이 아니라 **왜 그 칸이 있는가**다.

| 변하지 않는 원리 | 그래서 양식에 무엇이 |
|---|---|
| 받는 쪽이 다시 해석 안 하게 | 판정은 정해진 값(enum) 하나 |
| 루프가 끊기지 않게 | "다음 첫 행동"을 동사로 명시 |
| 거짓말을 코드로 잡게 | "받은 지시"와 "한 일"을 한 장에 |
| 메인이 가볍게 | 대화 전문 말고 한 장, 일회성 메모리 제외 |

→ 이 넷만 만족하면 5칸이든 12칸이든 맞는 양식. **개념을 이해하고 내 업무에 맞게 적용하는 것이 핵심.**

## 5. 외울 것만 추리면

- 나누는 이유 = **편향 · 환각 차단**(비용 아님).
- 두 방식의 차이 = **런타임을 빌리느냐(종속) 직접 짓느냐(분리)**, 종속형엔 오염 경로가 열려 있다.
- 핸드오프의 본질 = **형식 고정 → 결정성**. 모델 말고 형식을 믿는다.
- 좋은 핸드오프 = 한 장 · enum 판정 · 다음 행동 명시 · 지시와 결과 나란히.
- 9칸은 예시, **원리 4가지가 정답**.
- 마지막 반전 = **손으로 복사한 게 곧 spawn**(핸드오프 양식 = 서브에이전트 호출의 유저 프롬프트). 양식 잘 만들기 = 일 잘 시키기.
